## 20261102-07-a item 2 (MKT43-F2): why the slug was lost
WordPress core drops the `slug` that a user without publish rights sends with a Pending Review post or page (wp_insert_post: "Don't allow contributors to set the post slug for pending review posts"). The post keeps an empty slug, and on publish WordPress builds one from the title. Nostek Core did not cause it.

Fix in **Nostek Core 0.3.1** (PR #30, not merged yet):
- a `slug` sent with an unpublished post or page is stored in `meta.nostek_slug`;
- on the **first** publish that slug is used (made unique with `-2` if taken);
- **the publisher keeps sending exactly `{"status":"publish"}`**; do not add the slug there. A slug sent by the publisher would win, so leave it out.
- While pending, the REST `slug` field is empty; read back `meta.nostek_slug` to report the intended slug.
Nothing changes in A's save calls: keep sending `slug` as today.
